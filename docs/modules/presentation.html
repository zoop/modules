The problem shape

Many adjacent problems are the same pipeline.

Collect evidence → understand it → check it against truth → cost it → decide (auto or human).

Collect→ Understand→ Check→ Cost→ Decide

Motor claim

Photos + RC + estimate → damage, verify plate, cost repair, approve or investigate.

KYC onboarding

ID docs → read fields, match registries, flag forgery, pass or review.

Lending collateral

Asset photos → grade condition, check loan-on-asset, value it, lend or decline.

Build each one bespoke, and you rebuild the shape every time. That is the waste.

Execution model · for VP Eng + Architect

Two ways to call · two ways to orchestrate.

Every capability is reachable both ways R17

Sync — request / response

Low-latency, single-shot, bounded: "verify this PAN", "is this image tampered". Returns inline.

Async — case-based

Long-running, multi-stage, human-in-the-loop. 202 + case id → webhook on completion. Default for full products.

interactive> standard> batch

Priority classes + per-capability queues + per-tenant fairness. A Vision backlog never blocks Verify.

Two orchestration modes — same services underneath

Workflow Engine — deterministic DAG R1/R7

Pack-defined DAG over the case. Stages optional, partial-input tolerant, durable; pauses for human review for days; emits an event per transition. Default for structured products.

Agent Runtime — LLM drives R9

An LLM reasons over the case and calls capability services as tools. Guardrailed (incl. compliance), case-scoped memory, and a full reasoning trace that is itself an audit artifact. Powers agentic products.

Models & learning · for ML

Where models plug in, and how they improve.

We integrate and route models — own and third-party. We are not a model lab.

Model Gateway R10

Provider-agnostic access to LLM + vision models. Routing, fallback, versioning, cost/latency control.

Compliance-aware: never routes restricted PII to a non-compliant model or region; redacts before egress.

Used by Extract · Vision · Detect · Estimate · Agent Runtime.

Review + Feedback loop R6

The Review Console captures human decisions; corrections become labels. Designed so every correction improves the engine — the training loop is built in, not bolted on.

Eval / Model Registry R6

Versioned models + eval sets per pack. Designed to let us publish accuracy per capability, per pack (Phase 2+) — a differentiator in a market of vendor-claimed numbers. Not measured in prod today.

Vision / Extract / Detect→ Signals + provenance→ Human review→ Corrections → labels→ Eval + retrain

Compliance · a product USP

Compliant by construction.

A pack declares its regime (health/DPDP, insurance/IRDAI, lending/RBI, residency everywhere). The platform enforces it at runtime. Compliance is never re-implemented per product — so it's a selling point, not a per-product cost.

The one existential risk · and the discipline

Domain vocabulary leaking into the engine. (R4)

If "bumper", "fracture" or "room" ever appears in engine code, the thesis is dead — the engine has quietly become a vertical product. This is a discipline problem, and we guard it with two mechanisms.

The generic Signal model R2

Every stage writes typed signals to the case; downstream stages read the whole set, not each other's APIs. Detect's fused checks ("parts billed with no visible damage") are rules over a generic signal set — not code that knows about vehicles. Load-bearing: it's what makes a fused check domain-neutral.

The pack boundary

Feature vocabulary, sources of truth, price basis, risk rules and thresholds live only in a pack. If a new domain needs something the six pack slots can't express, that's a signal to extend the engine contract deliberately — never to special-case a domain in engine code.

The guardrail is architectural, not just a code-review rule: the engine speaks signals, the pack speaks domain.
